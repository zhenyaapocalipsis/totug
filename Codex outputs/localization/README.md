# Локализация EN/RU: подготовка L10n-0

Подготовлено 2026-11-05. План: ../plan_localization_ru.md.

## Результат этапа

- Собрана воспроизводимая инвентаризация из 177 исходных файлов и 20 JSON-файлов данных.
- Все 391 карты включены в cards_translation.tsv, с предложенными ключами card.<id>.name / card.<id>.ability и пустыми полями русского перевода.
- Составы 18 полуколод привязаны к картам. Включены также 31 запись вне составов, в том числе стартовые карты, запас и формы превращения.
- Подготовлен glossary_ru.md: 287 записей с пояснениями. Утверждены «возвысить» и «заменить», остальные переводы предложены.
- Составлены языковые правила и список зависимостей поведения от текста.
- Игровые исходники, изображения, настройки и механика на этом этапе не изменяются. Переключатель языка появится на L10n-1.

## Реестр

| Файл | Содержимое |
|---|---|
| inventory_summary.json | Числа, список входных файлов и SHA-256 для сверки с исходниками |
| source_strings.json | Все строковые литералы из игровых gd/tscn/project.godot, плюс три инструмента карточного рендера |
| data_strings.json | Все строковые значения игровых JSON с адресами JSON Pointer |
| cards_translation.tsv | Таблица всех карт для перевода; исходные английские поля и предложенные устойчивые ключи |
| text_dependencies.json | Найденные текстовые проверки поведения, требующие отдельного разбора |
| glossary_catalog.json | Машиночитаемый глоссарий со статусом каждой записи |
| glossary_ru.md | Рабочий глоссарий и различия терминов |
| language_policy_ru.md | Правила формулировок, чисел, имён и отображения |
| baseline.md | Результат исходных тестов и ограничения проверки |

В JSON инвентаризации 18 148 исходных литералов и 3 199 строковых значений данных. Это НЕ количество переводов: сюда специально включены внутренние идентификаторы, enum, пути и форматы, чтобы короткая подпись не потерялась из-за фильтра. Автоматическая категория — подсказка для разбора, не утверждение, что строку нужно переводить. Комментарии и тесты не включены. Из tools/ включены pixel_cards.gd, build_pixel_font.gd и alt_arts.gd; другие инструменты автора в пользовательскую локализацию не входят.

Реестр фиксирует места и исходный текст, но не собирает автоматически выражения из нескольких литералов. Устойчивые ключи интерфейса назначаются вручную после чтения целого выражения. Идентификаторы вида file:line:column служат для ревью снимка и не используются в игре как ключи перевода. Исходные escape-последовательности сохранены; в TSV обратная косая черта экранирована, реальные переводы строк представлены как \n. Файлы — UTF-8 без BOM. Список кандидатов не заменяет последующий поиск пропусков и визуальный обход экранов.

## Обновление реестра

Из корня проекта: node engine/tools/localization_inventory.cjs

Скрипт только читает игровые исходники и перезаписывает пять сгенерированных файлов реестра. Он НЕ перезаписывает глоссарий и правила языка. cards_translation.tsv — исходная заготовка этапа 0: перед началом перевода перенести подтверждённые записи в рабочие каталоги локализации; не вести единственный экземпляр перевода в регенерируемом файле.

## Что учитывать перед L10n-1 / L10n-2

1. Настройки доступны из меню и Esc. Оба входа должны использовать одно сохранённое значение English / Русский.
2. Смена языка в партии не отменяет выбор, не отправляет Intent, не меняет очередь эффектов. Уже открытые экраны и подсказки получают уведомление о языке.
3. decision_dialog.gd определяет сброс по starts-with Discard: сначала заменить на семантический признак, затем переводить подпись.
4. CardLive.RULES передаёт английские фразы; CardLiveFace ищет их в тексте. Нужны стабильные якоря условий и локализованные вставки.
5. OptionCard.NAMES индексируется английскими labels. Старые значения разрешать как совместимый ввод; отображение и заголовок переводить после определения варианта.
6. Названия мест участвуют в правилах стартовых локаций и бонусов. Переводить только представление; внутренние имена и site_id не заменять русскими.
7. Готовые PNG содержат английские надписи. Полные и мини-лица, альтернативные арты, живые поверхностные надписи требуют общего решения для текста. У кэшей должен быть язык в ключе.
8. PixelFont и pixel5.fnt уже поддерживают русский алфавит; отдельные FONT карточек и PixelFontSmall — нет. Проверять Ё/Й/Щ/Ъ и знаки, а не только латиноподобные буквы.
9. Диалоги и сетевые отказы местами несут готовые английские строки. Локализовать у получателя; язык клиента не должен влиять на серверные правила и сохранение повторов.
10. В реестре есть данные, не показанные сейчас, и технические имена прежних фракций. Не менять noxus/shurima/ionia/piltover в логике при переводе актуальных отображаемых Avernus/Calimshan/Kara-Tur/Waterdeep.
