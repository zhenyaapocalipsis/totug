# Game server (VPS)

- Host: `129.101.123.70` (Ubuntu 24.04), SSH as root with key `~/.ssh/tyrants_vps` (no password login needed).
- Game: `/opt/tyrants/godot` (official Godot 4.7.2 Linux build) + `/opt/tyrants/tyrants_server.pck`, run as user `tyrants`.
- Service: `tyrants` (systemd, file `server/tyrants.service`), restarts itself and starts on boot. UDP port 7780 open in ufw.
- Update after any network/rules change: `bash server/deploy.sh` (Git Bash). Bump `NetSession.PROTOCOL` when old clients must not join.
- UI/updater-only release: `bash server/deploy.sh --client-only`. Publishes the client and download ZIP without replacing the server pack or restarting rooms. Do not use for rules/network changes. The updater downloads on a worker thread with a 1 MiB buffer, independent of the client's FPS, and shows MiB/s. Existing clients acquire this fix through one final update using the old downloader.
- Local updater speed regression: `node engine/godot/tests/updater_download_test.cjs` (optional second argument: Godot console executable). Downloads and verifies a 4 MiB fixture at 10 FPS using both old defaults and the current updater; no internet required.
- **Binary patches (Stage Upd-2):** deploy requires Node.js on the build PC. Before export, `update_patches.cjs archive` preserves the exact previous signed PCK in `engine/build/releases/<build>/`. After export, `generate` produces direct deltas from up to five retained versions in `engine/build/patches/<new-build>/`. Content-defined blocks reuse unchanged bytes even when offsets move. Patches larger than 90% of the full package are omitted. Do not delete release history if you want those clients to receive small patches.
- Prepare without publishing: `bash server/deploy.sh --client-only --build-only`. Verify the real delta with `Godot --headless --path engine/godot --script res://tests/patch_release.gd -- <absolute-build-dir> <absolute-archived-base.pck>`, then publish the exact prepared artifacts with `bash server/deploy.sh --client-only --publish-only`. This validates signatures/hashes, retains `.previous` rollback files on the VPS and checks that the game server PID stays unchanged. Full deployment remains `bash server/deploy.sh` for rules/network changes.
- `version.txt` keeps its original first three fields and appends `<index-sha256> <index-signature>`. The immutable `patches/<build>/index.json` lists base hashes, patch hashes/sizes, target hash/size and build. The client verifies both RSA signatures, the index, patch and reconstructed package. A failed or unavailable patch falls back to the full package once; interrupted patch transfers retry once, and a 30-second transfer stall stops indefinite waiting. The original PCK remains intact until the verified replacement is ready. No patch chain or extra software on player PCs is required. A client predating Upd-2 needs one full migration download.
- Patch integration tests: `node engine/godot/tests/updater_patches_test.cjs`. Uses a local HTTP server, temporary RSA keys and real Godot clients to check small patches, skipped versions, reparenting, interruption/stall handling, signatures, damaged deltas and full fallback. Temporary fixtures never touch the owner's keys or game files.
- Logs: `ssh -i ~/.ssh/tyrants_vps root@129.101.123.70 journalctl -u tyrants -f`
- Ratings (Elo of online games): `/opt/tyrants/.local/share/godot/app_userdata/Tyrants of the Underdark/ratings.json` (appears after the first rated game). `deploy.sh` only replaces the .pck, so ratings survive updates; back the file up now and then.
- Bug reports (Stage Bug-1, the BUG REPORT button): one folder per report in `.../app_userdata/Tyrants of the Underdark/bug_reports/` (report.txt, screen.jpg, log.txt, game.replay; the newest 300 are kept). `bash server/fetch-bugs.sh` downloads them to `Claude outputs/bug_reports/`.
- Auto-update: nginx (config `server/nginx-tyrants.conf`) serves `/opt/tyrants/www` at `http://129.101.123.70/tyrants/` — `game.pck` and `version.txt` ("<build> <sha256> <signature>") plus `TyrantsOfTheUnderdark.zip` (download link for new players: http://129.101.123.70/tyrants/TyrantsOfTheUnderdark.zip). `deploy.sh` stamps the build number (`engine/godot/build_info.gd`, not in git), uploads the new game and refreshes `GAME online/`. Clients: `scenes/updater.gd`.
- GitHub download (2026-10-24): the same zip is a release asset, permanent link https://github.com/zhenyaapocalipsis/totug/releases/download/client/TyrantsOfTheUnderdark.zip (release tag `client`, the asset is replaced each time). `bash server/github-release.sh` uploads it; `deploy.sh` runs it at the end when GitHub CLI (`gh`) is installed and logged in (`gh auth login`, once).
- Update signing key (Stage Sec-1): clients install an update only if `version.txt` carries a valid RSA signature of "<build> <sha256>" (`scenes/update_sign.gd`). The private key is `~/.ssh/tyrants_update.key` on the owner's PC only — never in git, keep a backup copy (USB stick). If it is lost, installed games can no longer be updated (players re-download the zip). The public half is `engine/godot/scenes/update_key.gd`. Create once: `"C:\godot\Godot_v4.7.2-stable_win64_console.exe" --headless --path engine/godot --script res://tools/sign_update.gd -- --genkey` (refuses to overwrite an existing key). `deploy.sh` signs automatically and stops if the key is missing.
